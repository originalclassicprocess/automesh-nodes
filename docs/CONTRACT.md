# Контракт ядра и границы этапов

## Неизменные wire v1

`automesh-node-v1`, `automesh-opaque-mailbox-v1`, `automesh-courier-v1`,
`automesh-attachment-v1`, адреса mesh/Bech32m, байты подписи и MAE не изменены.
20 MiB — текущая политика файла, не новый wire-format. Старым клиентам
не нужны seed-миграция или повторная регистрация из-за переноса исходников.

Нода получает только подписанное задание и непрозрачный packet/части. ACK
сохранения на ноде не равен доставке; квитанция получателя появляется после
проверки/сохранения клиентом. ID и digest защищают от замены содержимого при
повторе. Подтверждённый текст/файл не планируется второй раз после рестарта,
пока живёт tombstone. TTL ограничивает содержимое и защиту повторов.

## Адаптеры

`packages/runtime/src/index.js` — программный Node.js API: `createNodeService`,
авторизация, ящики, части файлов, Courier, signal registry, secret envelope.
Создание сервиса не открывает listener автоматически: это решение runner.

Windows runner отвечает за bind, эксклюзивный контрольный порт, TLS/CA,
DPAPI/ACL, конфигурацию и жизненный цикл. Серверный Linux runner 0.4.0 имеет
внешний credential protector, kernel flock, HTTPS, systemd/proxy templates
и отдельное локальное управление; см. `SERVER_NODE.md`.
Браузеру потребуются собственные storage/network/lifecycle adapters: Node.js
runtime с `fs` нельзя просто импортировать в вкладку. Протокол уже общий.

## Управление профилями сейчас

`POST /members/remove` только в локальном control API, с Bearer adminToken,
без Origin; JSON `{ "address": "mesh1…", "confirm": "remove-node-data" }`.
Доступ отзывается перед удалением. Сохраняется `pendingRemovals`; cleanup
идемпотентен и возобновляется до listeners/routes. Удаление первого профиля
не перемещает и не смешивает ящики: immutable `primaryAddress` определяет
старую директорию; `owner` становится одним из оставшихся профилей или null.
Поля state добавлены обратно совместимо; бинарный downgrade после удаления
первичного профиля не поддерживается — старый код не знает `primaryAddress`.

Полный статус всех профилей доступен только администратору. `/outbox/status`
профиля содержит его собственные счётчики; общие ёмкость и состояние маршрута
не являются данными сообщений. Connect/scoped grants и подтверждение обеих
сторон — будущий этап, не выдаются за реализованные.

## Что не входит в этапы 1–2

Server deployment, публичный интернет-приём, перенос в GitHub, новый общий
web UI, Connect approval, федерация сигналингов, автоматическая цепочка нод,
3-hop mesh, Tor/I2P/VPN/proxy, Android/iOS/browser runtimes.

После этапов 1–2 проект опубликован отдельно, добавлен server runner preview.
Deployment, подключение домена в выпущенном клиенте, Connect/web UI и
автоматический node-to-node входящий приём всё ещё отдельные этапы.

Перед цепочкой нод нужно определить и отдельно версионировать hop envelope:
TTL/hop budget, dedup, подтверждение durable handoff, loop prevention,
право пересылки, маршруты и квоты. Эти поля не добавлены фиктивно в v1.
Разделение runtime/протокола позволяет внедрить это позже, не менять seed/MAE
и не объявлять существующие relay hops доказанным маршрутом доставки.
