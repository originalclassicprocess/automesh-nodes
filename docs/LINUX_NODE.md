# Linux x64: личная нода 0.4.5 preview

Новый адрес приложения по умолчанию — `https://automesh.online`; мастер позволяет
указать свой HTTPS-origin. Ранее сохранённые настройки не переписываются.

Скачать `Automesh-Node-Linux-x64.tar.gz` из Automesh → Настройки → Связь и
ноды → Мои ноды. Сверьте SHA-256 командой `sha256sum` с показанным описанием.
Это проверка совпадения, не независимая подпись издателя. Пакет пока тестовый.

Нужен Linux x64 с glibc (не Alpine/musl), `/usr/bin/flock` из util-linux,
долговечный диск, действующий HTTPS-сертификат и доступный доменный адрес.
Node.js 24.21.0 и runtime-зависимости включены; npm устанавливать не нужно.
ПК можно использовать свой, аренда сервера не обязательна. Для доставки из
другой сети понадобится доступный маршрут: пакет не обходит NAT автоматически.

Распакуйте архив в НОВУЮ папку в своём домашнем каталоге. Не запускайте от root.
В терминале этой папки:

```sh
./automesh-node help
./automesh-node setup
./automesh-node start
```

Первичная настройка спросит HTTPS-адрес, порт и пути к обычным PEM-файлам
сертификата и ключа. Симлинки, небезопасные права и несовпадающий сертификат
не принимаются. Приватный ключ должен быть вашим либо root-owned, с правами
600. Новый приватный каталог `~/AutomeshNode` создаётся только один раз;
повторная настройка не сбрасывает идентификатор, ключи или очередь.

В другом терминале выполните `./automesh-node admin-setup`, затем откройте
HTTPS-адрес ноды в браузере → Войти → подтвердите аккаунт в Automesh и введите
код первого назначения администратора. Seed и пароль ноде не нужны.
Приглашения выдаются из панели; доступ к очереди не даёт права администратора.

Оставляйте терминал и компьютер включёнными без сна. Остановка Ctrl+C
сохраняет очередь. После перезагрузки снова выполните `start`. Для автозапуска
оператор может настроить службу по [инструкции сервера](SERVER_NODE.md);
мастер не устанавливает службу, firewall или доверенный корневой сертификат.
Control-port 3004/3005 нельзя открывать наружу. TLS-сертификат нужно обновлять.

Обновление: остановить процесс, распаковать новую сборку в отдельную папку,
запустить её командой `start` — каталог данных остаётся прежним. Не запускать
`setup` заново и не генерировать новый master.key. Резервная копия должна
включать защищённый master.key; одна очередь без него не восстанавливает ноду.
После каждой сборки пакет сам проверяет файлы перед запуском. Проверка не
защищает от атакующего, способного заменить одновременно проверяющий код,
manifest и бинарник; для публичного выпуска нужна независимая подпись.

Пакет не делает телефон постоянно работающей нодой, не содержит TURN,
маркетплейс, оплаты или автоматическую маршрутизацию между всеми нодами.
