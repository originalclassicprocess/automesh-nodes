# Панель серверной ноды

В этой итерации добавлена панель на корневом HTTPS-адресе ноды. Требуется
обновлённый клиент Automesh с подтверждением входа. Старая версия сайта
сама по себе не получает новую функцию. Межнодовые мосты не включены.

## Первое назначение администратора

После обновления и запуска ноды владелец сервера получает отдельный код:

```sh
node adapters/passenger/main.js admin-setup /PRIVATE/config.json
```

Для VPS используется `adapters/server/main.js` с теми же аргументами.
Команда использует существующий закрытый loopback control, не публичный URL.
Код действует 10 минут, только до первого назначения. Перезапуск его отменяет.
Не публикуйте вывод, не передавайте его поддержке и не кладите в Git.

1. Откройте HTTPS-адрес ноды → «Войти через Automesh».
2. Откройте ссылку или отсканируйте QR телефоном с Automesh.
3. Разблокируйте нужный профиль. Если он уже открыт в другой вкладке того же
   браузера, запрос передаётся туда через same-origin BroadcastChannel.
4. Сверьте домен, ID и шестизначный код сверки с **своей** панелью ноды.
5. При первом входе вставьте код назначения администратора. Подтвердите управление.
6. Вернитесь в исходную вкладку ноды: вход завершится автоматически.

Далее нужен только этот профиль и осознанное подтверждение; пароль и seed
на ноду не вводятся. Администратор отдельный от восьми почтовых привязок.
Удаление профиля/первого ящика не назначает нового администратора.
Для восстановления самого профиля сохраняйте его резервную копию; панель
не позволяет другому аккаунту присвоить права. Принудительная смена
администратора и восстановление владельца пока не реализованы.

## Подключение клиентов

Скопируйте WSS-адрес в «Настройки → Подключения → Серверы подключения»
обновлённого приложения. Получатель должен подключаться к тому же сигналингу.
Приглашение профиля — **отдельная** кнопка: одноразовый JSON/QR на 10 минут,
вставляется в подключение своей ноды. Оно даёт доступ к очереди, не к панели.

В панели: связь, занятое место, конверты, восемь привязок, очередь/файлы
каждого профиля, новый код/QR, отключение профиля с явным подтверждением.
Удаление уничтожает только очередь выбранного профиля на ноде; история
в клиентах не удаляется. Перед удалением сделайте резервную копию при необходимости.

Лимиты показываются, но не редактируются в панели: 20 МиБ на файл,
64 МиБ общей очереди по умолчанию, восемь привязок. Изменение общей квоты,
origins, адреса и сигналинга пока через приватный config и перезапуск.

## Границы защиты

- Подписанное подтверждение связано с nodeId, каноническим HTTPS-адресом,
  короткоживущим запросом и назначением `node-admin-v1`. Повтор запрещён.
- Нельзя назначить первого администратора простым посещением сайта или
  обычным кодом привязки. bootstrap доступен только владельцу local control.
- Секрет опроса остаётся в инициирующей вкладке, не попадает в QR/ссылку.
  Одобрение в Automesh не возвращает управляющую сессию.
- Сессия панели — случайный HttpOnly/Secure/SameSite=Strict cookie, 15 минут,
  в RAM. Перезапуск/выход завершают сессию. Изменения требуют exact Origin
  самой ноды и отдельного CSRF-заголовка; Automesh не получает cookie.
- Администратор хранится в отдельном зашифрованном `panel-admin.json`.
  Повреждённый или пропавший после инициализации файл не сбрасывается
  автоматически. Backup включает этот файл и `state.json`.
- Статика только локальная, без CDN/трекеров; CSP запрещает встраивание панели.
  Проверяйте код сверки: чужой запрос входа может дать сессию чужой вкладке.
- Владельца/root/процесс того же Unix-пользователя эта схема не изолирует.
  Она не является защитой от подменённого клиента Automesh или XSS на нём.
- Windows/LAN runner не получает публичную панель и её auth routes.

Обновлять нужно обе части: ноду (включая каталог `ui/`) и приложение.
Установка SSL без обновления кода панели не создаёт.
