# Границы безопасности ноды

Это preview, не независимый криптографический аудит и не обещание анонимности.

- Seed, закрытые ключи профилей, HPKE-prekeys и ключи файлов остаются в клиенте.
  Нода хранит непрозрачные конверты/части, но видит адреса, объёмы и время.
- Ядро требует явно переданный SecretProtector `{ protection, protect,
  unprotect }`. Без адаптера запуск запрещён. Windows использует DPAPI
  CurrentUser; Linux/server использует AES-256-GCM с внешним OS credential
  (см. `docs/SERVER_NODE.md`). Тестовый адаптер
  существует только для автотестов, не является вариантом серверной защиты.
- DPAPI защищает от чтения копии диска вне Windows-пользователя; не защищает
  от вредоносного кода с правами этого пользователя/администратора.
- HTTPS API и WSS доступны только выбранным частным IPv4 (до 16) и loopback через Windows
  runner. Управление — отдельный loopback-порт + Bearer-token, без браузерного
  Origin. Не публикуйте этот порт через reverse proxy/port forwarding.
- Linux/server: HTTPS bind по умолчанию loopback за проверяющим TLS proxy;
  публичный bind возможен только явной настройкой. Control остаётся loopback.
  Master/TLS key вне данных; encrypted systemd credentials рекомендуются.
  Не защищает от root/компрометации работающего процесса или полной копии
  сервера с host-key. Один writer обеспечивается Linux kernel flock.
- Запросы подписывают точные тело, путь, метод, nodeId и одноразовый challenge
  на 30 секунд. Проверяются связь ключа с адресом, членство и разрешённый sender.
- Диск/сообщения/части/число профилей/отправителей ограничены. Файлы до 20 MiB.
  Выдача файла требует подписи указанного получателя. LAN-only не выходит
  через интернет-маршрут. Подписи и MAE/HPKE не менялись при выделении ядра.
- Подтверждение сохранения — после fsync/atomic rename; дедупликационные
  tombstones живут до TTL. Удаление синхронизируется с диском на POSIX.
  Windows не поддерживает directory fsync; абсолютной гарантии при потере
  питания/неисправном диске нет. Повреждённые подтверждённые данные не сбрасываются.
- Отключение профиля сохраняет отзыв доступа перед очисткой очередей. Пока
  очистка не завершена, адрес нельзя перепривязать. Восстановление происходит
  до запуска маршрутов. Данные удаляются логически, не как secure erase SSD.
- Отключение не стирает клиентские резервные копии/seed и не инвалидирует ключ
  адреса во всей сети. Уже отправленные данные вернуть нельзя. Клиент может
  предложить повторную загрузку своих ожидающих сообщений после новой привязки.
- Отключение профиля не блокирует его публичный LAN-сигналинг: сигналинг
  самостоятельная служба знакомства устройств, не доступ к ящику/очередям.

Перед deployment обязательны: проверка admin-доступа/firewall/proxy именно на
хостинге, долговечный диск, обновления/ACME, restore резервной копии.
Server runner включает подписанный HTTPS inbox и согласие администратора
через Automesh; входящие получателя не требуют присутствия отправителя.
Automatic node-to-node/bridge и discovery произвольных нод не реализованы.
Windows-архив проверяется до записи (полнота, имена, отсутствие дублей,
размеры, SHA-256); после прерванного обновления launcher не запускает
несовпадающий backend. Секретный config сохраняется через случайный временный
файл с exclusive create и flush, затем атомарную замену.
Контрольные суммы пакетов НЕ равны независимой подписи издателя. Installer
остаётся unsigned preview; подмена сайта/кода проверки ими не устраняется.
Не менять bind на `0.0.0.0` у Windows-runner как замену серверному адаптеру.
